## Deterministic "My Form" photo fixtures

Task 8's Playwright and Maestro coverage for the "My Form" pipeline runs against the real,
default `HeuristicSilhouettePhotoModerationEngine` (decisions 8-9 of this story), not a
stubbed outcome. `wardrobe-silhouette-image-validation.ts` decodes real image bytes before any
moderation engine runs, so the `FixtureSilhouettePhotoModerationEngine`'s
`FIXTURE:<outcome>:` byte-marker convention (used by the API's own integration tests, which
exercise the pipeline at the service/queue/worker seam with a storage double) cannot reach a
genuine end-to-end upload through a browser or a mobile picker — that marker is not decodable
image bytes.

Instead, two committed fixture PNGs (`playwright/fixtures/wardrobe/silhouette-photo-ready.png`,
`playwright/fixtures/wardrobe/silhouette-photo-contrast.png`) and one bundled mobile asset
(`apps/mobile/assets/images/silhouette-my-form-fixture.png`) are engineered so the real
heuristic's border-vs-center contrast measurement deterministically lands on a known verdict:

- All three images are portrait-framed (height:width = 4:3, well over the required 1.2
  minimum ratio) and 3-channel PNGs with no transparency.
- `silhouette-photo-contrast.png` is a single flat color across the entire image. The
  heuristic's border sample (the top 8% strip) and center sample (the middle 50%×50% region)
  are therefore identical, so the measured Euclidean RGB distance is exactly 0, always below
  the engine's `contrastThreshold` of 40 — a deterministic `contrast` verdict.
- `silhouette-photo-ready.png` and the mobile fixture fill the whole canvas with one
  background color and draw a second, distinct, non-skin-toned color (navy blue,
  `rgb(20, 80, 160)`) over exactly the engine's own center-sample rectangle. The measured
  distance (~292) clears the contrast threshold, and the skin-tone heuristic never matches a
  blue pixel, so the verdict is deterministically `ready`.
- All three verdicts were confirmed directly against the real
  `HeuristicSilhouettePhotoModerationEngine` class before being wired into any spec or flow
  (not merely assumed from the arithmetic above), and again transitively via the real
  Playwright runs recorded in the table above, which show the actual `ready`/`contrast`
  outcomes logged by the running API.

The mobile `silhouette-editor.tsx` gained a `__DEV__`-only
`silhouette-my-form-fixture-source` button (mirroring `garment-capture-modal.tsx`'s existing
`garment-e2e-fixture-source` pattern) because no deterministic way otherwise exists to drive a
real camera/library picker from Maestro. It is stripped from production builds like its
garment-capture sibling.
