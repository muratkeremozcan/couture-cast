## Codex Security pass

- Checked the two account-isolation paths above separately on web, native and direct SQL. The
  NestJS list, get and delete queries scope rows to the authenticated owner. Garment lookup
  requires the same owner, ready upload status and active retention. These checks do not bind
  a stale catalog-only create to its initiating client session.
- The migrated table has RLS and the intended direct-write restrictions. The installed
  SELECT policy delegates to the broader shared helper. PostgreSQL tests covered ordinary owner,
  unrelated authenticated user, anon, write grants, uniqueness and cascading account deletion.
- Photo URLs come from the storage adapter after stored object-path ownership checks. The teen
  photo gate returns null image access when strict wardrobe access fails. Pending-mode coverage
  uses the required-consent policy or mocks. The shipped policy is off, and its migration
  activated previously pending members. The saved-look middleware sets
  `private, no-store` before guards and handlers. Review found no request-controlled URL signing
  sink, raw SQL interpolation on API inputs, or raw HTML rendering of saved-look text.
- The per-owner unique key and qualified atomic DELETE prevent parallel writes from bypassing
  the server's same-key and revision checks. The review found a gap after hard deletion, along with client key lifetime and replay/Undo issues.
